# 文件引用规范 (Relative Links Only)

1. 所有 Markdown 内部交叉引用**必须使用相对路径**。
2. **严禁绝对路径**，包括 `file:///Users/...` 与 `/Users/...` 两种形式。

---

## 为什么（设计原因，供理解而非死记）

绝对路径**绑定单台机器的用户名与目录结构**。仓库一旦克隆到其他电脑、或更换用户名，全部内部跳转立即失效。此外，绝对路径在 **GitHub 网页端的 Markdown 渲染中完全不可点击**。

---

## 怎么写

一律以**当前正在编辑的文件所在目录**为基准计算：

- 同目录 → 直接写文件名：`01_sentence_lego.md`
- 子目录 → 写相对子路径：`daily_logs/2026-09-30.md`
- 上级目录 → 用 `..` 回退：`../MEMORY.md`

---

## 收尾校验

3. 任何**新增、移动或重命名链接**的改动，完成前必须逐条验证链接可解析到真实存在的文件。
4. **删除或重命名文件前，必须先全库搜索该文件名的引用**并同步清理，避免留下断链。
5. 区分两类引用：真实的 Markdown 链接 `[文字](路径)` 必须修复；反引号包裹的纯文本提及 `` `文件名.md` `` 不会断链，按第六节判断是否保留。

---

## 例外

6. **历史日志不得改写**：`daily_logs/` 下既有文件中对已删除文件的纯文本提及，属于**历史事实记录**。不得为了让引用「看起来有效」而篡改历史。
7. **`.qoder/rules/` 下的规则文件只支持自然语言**——Qoder 会忽略其中的图片与超链接。规则文件里的路径一律用反引号包裹的纯文本，**不要写成 Markdown 链接**。
8. 代码块内的目录树示意（如 `README.md` 的项目结构图）用相对根名即可，不要写机器绝对路径。
